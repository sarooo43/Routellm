# Code of conduct

## The short version

Be decent. Assume good faith. Critique the code, not the person who wrote it.

## Expected behaviour

- Discuss ideas and code directly and respectfully. Disagreement is fine;
  contempt is not.
- Give reviews that explain *why*, and that a newcomer can act on.
- Accept that maintainers may decline a change — scope is a real constraint on
  a small project.
- Respect privacy: do not publish someone's keys, logs, hostnames or personal
  information, even in a bug report where it seemed harmless.

## Unacceptable behaviour

- Harassment, insults, or personal attacks.
- Discriminatory language or imagery on the basis of identity.
- Sustained disruption of discussions or issues.
- Publishing another person's private information without permission.
- Using the project's channels to promote unrelated commercial offerings.

## Scope

This applies in issues, pull requests, discussions and any other space the
project uses to collaborate, and when representing the project elsewhere.

## Reporting

Report a problem privately through GitHub (Security → Report a vulnerability
routes to the maintainer's inbox) rather than in a public thread. Reports are
read by the maintainer; the reporter's identity is kept private.

## Consequences

Maintainers may edit or remove comments, close threads, or block accounts.
The usual progression is a request to stop, then moderation; a single serious
incident can skip straight to a block.

---

This code of conduct is intentionally short. It is a statement of expectations,
not a legal document.
